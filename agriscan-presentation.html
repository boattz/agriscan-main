01 — ภาพรวม

โปรเจกต์นี้คืออะไร?

Agriscan คือระบบ IoT สำหรับการเกษตร ตรวจวัดสภาพดิน 7 อย่างแบบเรียลไทม์ ตั้งแต่ระดับฮาร์ดแวร์จนถึงหน้าจอแสดงผล — สร้างด้วยหลักการ "เรียบง่ายที่สุดที่ใช้งานได้จริง"

01 · ฮาร์ดแวร์
ESP32 + เซ็นเซอร์ 7-in-1
เซ็นเซอร์ฝังดินอ่านค่า 7 อย่าง (ความชื้น, อุณหภูมิ, EC, pH, N, P, K) ส่งผ่านสาย RS485 Modbus 2 เส้นให้ ESP32
02 · ตัวกลาง
ESP32 ทำทุกอย่างในตัวเดียว
อ่านค่าเซ็นเซอร์, เสิร์ฟหน้า Dashboard ในเครือข่ายท้องถิ่น และ POST ค่าจริงขึ้นคลาวด์ทุก 1 นาที (HTTPS + API key)
03 · การแสดงผล
Dashboard เว็บ + คำแนะนำ
หน้าเว็บ Vanilla HTML/CSS/JS ดึงข้อมูลทุก 5 วินาที — เปิดบนคลาวด์ดูจากที่ไหนก็ได้ พร้อมวิเคราะห์และแนะนำการดูแลดินอัตโนมัติเป็นภาษาไทย
เพิ่มเติม มี Backend Flask + PostgreSQL อยู่บนคลาวด์ (Render.com) — รับค่าจริงจาก ESP32 เก็บประวัติลงฐานข้อมูล และเสิร์ฟ dashboard ให้ดูได้จากทุกที่
02 — เซ็นเซอร์

ค่าที่วัดได้และช่วงปกติ

ระบบอ่านค่า 7 อย่างจากเซ็นเซอร์เดียวกันผ่านโปรโตคอล Modbus RTU โดยอ่าน Holding Registers 0x0000–0x0006 ต่อเนื่อง 7 ตัวในคำสั่งเดียว

ค่าหน่วยช่วงปกติสถานะผิดปกติความหมาย
ความชื้น (Moisture) %30–80 < 30 แห้ง > 80 ชื้นเกิน น้ำในดิน ต่ำ = ควรรดน้ำ สูง = รากเน่าได้
อุณหภูมิ (Temperature) °C15–35 < 15 เย็น > 35 ร้อน ความร้อนในดิน ส่งผลต่อการดูดซึมของราก
EC (การนำไฟฟ้า) µS/cm100–2000 < 100 ต่ำ > 2000 เค็ม ความเข้มข้นเกลือ/ธาตุอาหาร สูงเกิน = ดินเค็ม
pH ดิน pH5.5–7.5 < 5.5 กรด > 7.5 ด่าง ความเป็นกรด-ด่าง มีผลต่อการดูดธาตุอาหาร
ไนโตรเจน (N) mg/kg≥ 50 (ค่าบ่งชี้) < 50 ธาตุหลัก เร่งใบ — กรมฯ วัด N เป็น % ค่าเซ็นเซอร์เป็นค่าประมาณ
ฟอสฟอรัส (P) mg/kgต่ำ <10 · ปานกลาง 10–25 · สูง >25 < 10 ต่ำ 10–25 ปานกลาง เร่งราก ดอก ผล — เกณฑ์กรมพัฒนาที่ดิน
โพแทสเซียม (K) mg/kgต่ำ <60 · ปานกลาง 60–90 · สูง >90 < 60 ต่ำ 60–90 ปานกลาง เสริมความแข็งแรง ต้านทานโรค — เกณฑ์กรมพัฒนาที่ดิน
จุดน่าสนใจ ค่า EC ไม่ได้วัด "เกลือ" โดยตรง — แต่วัดความสามารถในการนำไฟฟ้าของน้ำในดิน ซึ่งสะท้อนความเข้มข้นของธาตุอาหารที่ละลายอยู่ ถ้าสูงเกินไปแสดงว่าดินเค็ม (จากปุ๋ยหรือน้ำทะเล) ทำให้พืชชะงักการเจริญเติบโต
แหล่งที่มาของเกณฑ์ เกณฑ์ P, K, EC, pH อ้างอิงจาก กรมพัฒนาที่ดิน — คู่มือการวิเคราะห์ดินทางเคมีเพื่อประเมินความอุดมสมบูรณ์ของดิน, ตารางที่ 15 (กองสำรวจดิน, 2523): P ต่ำ <10 · ปานกลาง 10–25 · สูง >25 mg/kg · K ต่ำ <60 · ปานกลาง 60–90 · สูง >90 mg/kg — ส่วน N (mg/kg), ความชื้น และอุณหภูมิ ไม่มีเกณฑ์จากกรมฯ (N วัดเป็น %, ความชื้นขึ้นกับชนิดดิน) จึงแสดงเป็นค่าบ่งชี้/ข้อมูลประกอบ — ลิงก์ตรงที่เปิดได้: e-library.ldd.go.th/library/flip/bib10134f/files/basic-html/page83.html
03 — สถาปัตยกรรม

โครงสร้างโปรเจกต์

สามส่วนหลักแยกจากกันชัดเจน: firmware บน ESP32, dashboard ที่เปิดได้ทั้งจากเครื่องและฝังอยู่ในตัว ESP32, และ backend จริงบนคลาวด์ (Flask + PostgreSQL)

esp32/agriscan/ agriscan.ino ← firmware: RS485 + WiFi + WebServer dashboard.h ← dashboard ฝังใน C++ raw string dashboard/ index.html ← หน้าเว็บ standalone script.js ← logic, IP fallback, คำแนะนำ style.css ← dark green glassmorphism backend/ app.py ← Flask API จริง + PostgreSQL (Render.com) requirements.txt render.yaml ← config deploy บน Render
หัวใจของดีไซน์
ESP32 คือระบบที่สมบูรณ์ในตัวเอง
  • dashboard.h ฝังหน้าเว็บทั้ง HTML/CSS/JS เป็น C++ string literal → ESP32 เสิร์ฟเองได้ ไม่ต้องพึ่งอินเทอร์เน็ต
  • dashboard/ เป็นเวอร์ชัน standalone เดียวกัน เปิดจากเครื่องหรือ deploy กับ backend ได้
  • ESP32 → คลาวด์: ส่งค่าจริงขึ้น Render ทุก 1 นาที เก็บลง PostgreSQL — ดูข้อมูลจากที่ไหนก็ได้
  • สองเวอร์ชันนี้ต้องซิงค์กันด้วยมือ (ไม่มี build script)
เทคโนโลยี
สแตกทั้งหมด
  • ESP32: ModbusMaster (Arduino library)
  • Frontend: Vanilla HTML/CSS/JS — ไม่มี framework, ไม่มี build step
  • Backend: Flask 3.0.3 + flask-cors + gunicorn + PostgreSQL (psycopg)
  • Fonts: Prompt (ไทย) + JetBrains Mono (ตัวเลข)
04 — Firmware ESP32

ESP32: ตัวกลางแปลงเซ็นเซอร์เป็นเว็บ API

โค้ด Arduino C++ ใน agriscan.ino ทำหน้าที่: อ่านค่า Modbus → เก็บค่าในหน่วยความจำ → เสิร์ฟ JSON ให้ dashboard ท้องถิ่น และส่งค่าจริงขึ้นคลาวด์

การต่อฮาร์ดแวร์
RS485 ↔ ESP32
RX (รับข้อมูล)GPIO 16
TX (ส่งข้อมูล)GPIO 17
DE/RE (ควบคุม MAX485)GPIO 4
Baud rate9600 · 8N1
Modbus Slave ID1
Web Server (พอร์ต 80)
API ของ ESP32
  • GET / → เสิร์ฟหน้า Dashboard (จาก dashboard.h)
  • GET /data → ค่าเซ็นเซอร์เป็น JSON พร้อม CORS เปิดทั้งหมด
  • POST /api/readings → ส่งค่าจริงขึ้นคลาวด์ทุก 1 นาที (HTTPS + X-API-Key)
  • mDNS → เข้าผ่าน http://agriscan.local ไม่ต้องจำ IP
วงจรการทำงาน
loop() ทุก 5 วินาที
  • รับ HTTP request ผ่าน server.handleClient() ตลอดเวลา
  • ตรวจ WiFi ถ้าหลุด → reconnect อัตโนมัติ
  • อ่านค่าเซ็นเซอร์ผ่าน Modbus (readHoldingRegisters(0x0000, 7))
  • อ่านสำเร็จ → อัปเดตค่า / ไม่สำเร็จ → ใช้ค่าเดิม (ระบบทนทานต่อการขาดการติดต่อชั่วคราว)
  • POST ค่าจริงขึ้นคลาวด์ทุก 1 นาที — สำเร็จ (201) / ล้มเหลว → ลองใหม่รอบถัดไป
การแปลงค่าจาก Register
Raw → หน่วยจริง
  • ความชื้น = reg[0] / 10
  • อุณหภูมิ = (int16)reg[1] / 10 (รองรับค่าลบ)
  • EC = reg[2] · pH = reg[3] / 10
  • N, P, K = reg[4..6] (mg/kg)
ตัวอย่าง JSON ที่ ESP32 ส่งขึ้นคลาวด์ (POST /api/readings)
// ESP32 → Render (ทุก 1 นาที) · dashboard GET /api/latest เห็นค่านี้
{ "moisture": 45.2, "temperature": 28.5, "ec": 320,
  "ph": 6.8, "n": 45, "p": 32, "k": 89,
  "valid": true }
05 — Dashboard

หน้าแสดงผลและ "สมอง" ของระบบ

แดชบอร์ด Vanilla JS ธีม dark green glassmorphism ภาษาไทย — ดึงข้อมูลทุก 5 วินาที พร้อมระบบหาที่อยู่ของ ESP32 อัตโนมัติ และแนะนำการดูแลดิน

องค์ประกอบ UI
บนหน้าจอมีอะไรบ้าง
  • Header: โลโก้, สถานะออนไลน์/ออฟไลน์ (ไฟกระพริบ), เวลาอัปเดตล่าสุด, ป้าย IP ที่เชื่อมต่ออยู่ (คลิกเปลี่ยนได้)
  • การ์ดเซ็นเซอร์ 5 ใบ: ความชื้น (มี progress bar สีเปลี่ยนตามสถานะ), อุณหภูมิ, EC, pH, NPK (กราฟแท่ง 3 สี)
  • คำแนะนำอัตโนมัติ: การ์ดวิเคราะห์ค่าแต่ละตัวแบบ real-time
  • Banner: แจ้ง "กำลังเชื่อมต่อ" และสถานะ offline — ไม่มีข้อมูลจำลอง
  • ลูกเล่น: ตัวเลขกระพริบเมื่อค่ามีการเปลี่ยนแปลง, skeleton loading, ปุ่มรีเฟรช
ระบบแนะนำอัตโนมัติ
ตัวอย่างคำแนะนำ (ภาษาไทย)
  • ความชื้น < 30% → "ควรรดน้ำทันที"
  • ความชื้น > 80% → "หยุดรดน้ำ — อาจรากเน่า"
  • pH < 5.5 → "ใส่ปูนขาว (Lime)" / > 7.5 → "ใส่กำมะถัน"
  • N < 50 → "ใส่ปุ๋ยสูตร 46-0-0 หรือ 21-0-0" (ค่าประมาณจากเซ็นเซอร์)
  • P < 10 → "ใส่ปุ๋ยสูตร 0-46-0" · 10–25 → "ปานกลาง ยังไม่ต้องใส่" (เกณฑ์กรมฯ)
  • K < 60 → "ใส่ปุ๋ยสูตร 0-0-60" · 60–90 → "ปานกลาง ยังไม่ต้องใส่" (เกณฑ์กรมฯ)
  • EC > 2,000 µS/cm → "เริ่มเค็มเล็กน้อย — ระวังการใส่ปุ๋ย"
  • อุณหภูมิ > 35°C → "คลุมดินเพื่อลดความร้อน"
Fallback Chain — ระบบหาตำแหน่ง ESP32 อัตโนมัติ (ลองตามลำดับ)
1IP ที่ผู้ใช้ตั้งเอง (localStorage)จำจาก session ก่อนหน้า
2URL ที่เชื่อมต่อสำเร็จล่าสุดเร็วสุดสำหรับการใช้งานซ้ำ
3Page Origin (หน้าเว็บที่เปิดอยู่)กรณีเปิดผ่าน ESP32 หรือคลาวด์โดยตรง
4https://agriscan-backend-l4vu.onrender.com/dataคลาวด์ Render — ค่าจริงจาก ESP32
5http://agriscan.local/datamDNS ของ ESP32 (เครือข่ายท้องถิ่น)
6http://192.168.1.1/datagateway ตอนใช้ hotspot
7http://localhost:5000/databackend รันในเครื่อง (dev)
การกันพลาด แต่ละ URL มี timeout 3 วินาที (AbortController) — ไม่มี mock data ถ้ายังไม่มีข้อมูล ระบบจะแสดงสถานะ offline ตามจริงและลองใหม่ทุก 5 วินาที / ทันทีที่กลับมาที่แท็บ จนกว่า ESP32 จะส่งค่ามา
06 — Backend & คลาวด์

Flask API + PostgreSQL — ข้อมูลจริงจาก ESP32

ESP32 ส่งค่าจริงขึ้นคลาวด์ (Render.com) เก็บลง PostgreSQL ทุก 1 นาที — dashboard บนเว็บดึงค่าจากฐานข้อมูล ไม่มีข้อมูลจำลอง

POST /api/readings
รับค่าจาก ESP32 (ต้องมี header X-API-Key) → บันทึกลง PostgreSQL
GET /api/latest
ค่าล่าสุดจากฐานข้อมูล (dashboard poll ทุก 5 วินาที) — /data เป็น alias เดียวกัน
GET /health
ตรวจสถานะ service + ฐานข้อมูล — คืน {"status":"healthy","db":"connected"}
Deploy จริงบน Render.com — ดูสดได้ที่ https://agriscan-backend-l4vu.onrender.com
# Deploy: Render อ่าน render.yaml → สร้าง Web Service + PostgreSQL ให้อัตโนมัติ
# render.yaml ตั้งค่า: DATABASE_URL (จาก database service) + API_KEY (สุ่มอัตโนมัติ)

# ทดสอบส่งค่าขึ้นคลาวด์ (เหมือน ESP32 ทำทุก 1 นาที)
curl -X POST https://agriscan-backend-l4vu.onrender.com/api/readings \
     -H "Content-Type: application/json" \
     -H "X-API-Key: <API_KEY>" \
     -d '{"moisture":45.2,"temperature":28.5,"ec":320,"ph":6.8,"n":45,"p":32,"k":89}'
# → {"success": true} (201) · key ผิด → 401
07 — ประเมินโปรเจกต์

จุดเด่นและข้อจำกัด

ส่วนนี้ช่วยตอบคำถามผู้ชมได้อย่างมั่นใจ — รู้ทั้งสิ่งที่ทำได้ดีและขอบเขตที่ยังไม่ได้ทำ

จุดเด่น

  • ดูได้จากทุกที่: dashboard บนคลาวด์ (Render) เปิดจากมือถือ/คอมพิวเตอร์ที่ไหนก็ได้ ข้อมูลจริงจากเซ็นเซอร์
  • Self-contained: ESP32 ยังเสิร์ฟ dashboard ให้เครือข่ายท้องถิ่นได้เอง (agriscan.local) แม้ไม่มีอินเทอร์เน็ต
  • ติดตั้งง่าย: ไม่มี build step, ไม่มี framework — deploy ผ่าน render.yaml อัตโนมัติ (Web + DB)
  • ข้อมูลจริงเท่านั้น: ไม่มี mock data — ค่าที่แสดงมาจากเซ็นเซอร์จริง เก็บประวัติใน PostgreSQL
  • ทนทาน: อ่านเซ็นเซอร์ไม่สำเร็จใช้ค่าเดิม, WiFi หลุด reconnect อัตโนมัติ, fallback chain 7 ระดับ
  • ใช้งานง่าย: UI ภาษาไทย + คำแนะนำบอกสูตรปุ๋ยเป็นตัวเลขชัดเจน

ข้อจำกัด (ต้องรู้ก่อนนำเสนอ)

  • แสดงผลอย่างเดียว: ไม่มี relay/actuator — ระบบแนะนำแต่ไม่ได้รดน้ำให้อัตโนมัติ
  • ยังไม่มีกราฟประวัติ: ข้อมูลเก็บลง PostgreSQL ครบ แต่ UI ยังแสดงเฉพาะค่าล่าสุด
  • WiFi hardcode: SSID/รหัสอยู่ในโค้ด ต้องแก้และ re-flash เพื่อเปลี่ยนเครือข่าย
  • ต้องซิงค์ 2 ชุดด้วยมือ: dashboard.h (ฝังใน ESP32) กับโฟลเดอร์ dashboard/
  • ความปลอดภัยแบบเบา: API key กันการส่งข้อมูลปลอม แต่ CORS ยังเปิดและ key ฝังใน firmware
08 — คู่มือนำเสนอ

แนวทางการสาธิต (5 นาที)

ลำดับการนำเสนอที่เล่าเรื่องได้ครบ: ปัญหา → วิธีแก้ → สาธิตจริง → จุดแข็ง → ต่อยอด

1

เปิดด้วยภาพรวม

"ระบบ IoT ตรวจวัดค่าดิน 7 อย่างแบบ real-time สำหรับเกษตรกร — รู้ทันทีว่าดินแห้ง ดินเค็ม หรือขาดธาตุอาหาร"

2

ชี้ฮาร์ดแวร์ให้เห็น

โชว์เซ็นเซอร์ฝังดิน → สาย RS485 2 เส้น → ESP32 อธิบายว่า "สาย 2 เส้นนี้พาค่า 7 อย่างไปได้ทั้งชุด"

3

สาธิตสด — ดูจากมือถือ

เปิด https://agriscan-backend-l4vu.onrender.com จากมือถือ โชว์ค่าจริงที่เปลี่ยนทุก 5 วินาที + เปิด Serial Monitor เห็น log [Cloud] POST 201 ทุก 1 นาที

4

โชว์ "สมอง" ของระบบ

ชี้การ์ดคำแนะนำ — "ถ้าความชื้นต่ำ ระบบบอกให้รดน้ำ ถ้า N ต่ำ ระบบบอกสูตรปุ๋ยให้เลย 46-0-0"

5

โชว์การกันพลาด

ปิด ESP32 → หน้าเว็บแสดง สถานะ offline ตามจริง (ไม่มี mock) แต่ข้อมูลล่าสุดยังอยู่บนคลาวด์ — พอ ESP32 กลับมาออนไลน์ ข้อมูลไหลต่ออัตโนมัติ

6

ปิดด้วยการต่อยอด

"ต่อไปเพิ่ม relay ควบคุมระบบน้ำอัตโนมัติ เก็บประวัติลง database และแจ้งเตือนผ่าน Line ได้"

คำถามที่ผู้ชมมักถาม "ข้อมูลแม่นไหม?" — ค่ามาจากเซ็นเซอร์จริงผ่าน RS485 Modbus เก็บลง PostgreSQL ไม่มีข้อมูลจำลอง  ·  "รองรับกี่แปลง?" — ตอนนี้ออกแบบมาสำหรับเซ็นเซอร์ชุดเดียว ต่อยอดเพิ่ม node ได้โดยใช้ Modbus ID ต่างกัน  ·  "ต้องมีอินเทอร์เน็ตไหม?" — โหมดคลาวด์ต้องมี (ESP32 ส่งผ่าน WiFi) แต่โหมด local (agriscan.local) ยังใช้ได้ในเครือข่ายเดียวกัน
